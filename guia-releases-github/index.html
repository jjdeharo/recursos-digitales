📦 Subir archivos de hasta 2 GB a GitHub

Cómo subir archivos de hasta 2 GB a GitHub y obtener una URL pública estable

Guía paso a paso para subir archivos ZIP, ELPX o H5P (hasta 2 GB) usando releases de GitHub y obtener una URL directa que no cambia aunque se actualice el archivo.

Todo desde el navegador Hasta 2 GB por archivo URL que no cambia al actualizar
Índice
1 Crear el repositorio 2 Crear una release 3 Subir el archivo 4 Obtener la URL directa 5 Actualizar el archivo 6 Publicar y compartir ✓ Resultado final

1 Crear el repositorio

  1. Entrar en github.com (crear una cuenta si no se tiene).
  2. Pulsar el botón + de la esquina superior derecha y seleccionar New repository.
  3. Escribir un nombre descriptivo (por ejemplo: recursos-educativos).
  4. Marcar el repositorio como Public para que cualquiera pueda descargar los archivos.
  5. Activar la casilla Add a README file.
  6. Pulsar Create repository.
¿Por qué es necesario el README? GitHub necesita al menos un archivo (un commit inicial) para poder crear releases. El README cumple esa función.

2 Crear una release

  1. Dentro del repositorio, hacer clic en Releases (en la barra lateral derecha).
    Si no aparece, añadir /releases al final de la URL del repositorio.
  2. Pulsar Draft a new release.
  3. En Choose a tag, escribir una etiqueta de versión, por ejemplo: v1.0. Seleccionar Create new tag cuando aparezca.
  4. En Release title poner el título del recurso.
    Ejemplo: «Proyecto biodiversidad 4º ESO».
Recomendación: un recurso por repositorio Para mantener URL estables con /latest/, lo más seguro es usar un único recurso/archivo por repositorio.

3 Subir el archivo (ZIP, ELPX o H5P)

  1. En la zona inferior de la release, localizar el área Attach binaries by dropping them here or selecting them.
  2. Arrastrar el archivo (ZIP, ELPX o H5P) sobre esa zona, o hacer clic para seleccionarlo.
  3. Esperar a que termine la subida (puede tardar con archivos grandes).
  4. Pulsar Publish release.
Límite de tamaño GitHub permite hasta 2 GB por archivo en una release.

4 Obtener la URL directa de descarga

Una vez publicada la release, en la sección Assets aparecerá el archivo subido. Usa la URL estable con /latest/:

Formato de la URL (sustituir las partes en naranja) https://github.com/USUARIO/REPO/releases/latest/download/archivo.ext
URL generada
Ventaja de la URL con /latest/ Siempre apunta a la versión más reciente. No es necesario cambiar la URL cuando se publique una nueva versión del archivo.
El nombre del archivo importa Para que la URL con /latest/ funcione correctamente, el archivo debe llamarse igual en cada nueva release. Si en la versión 1.0 se subió recurso.elpx, en la 1.1 también debe llamarse recurso.elpx.
No usar estos archivos Source code (zip) y Source code (tar.gz) contienen el código fuente del repositorio, no el archivo que se ha subido. Se deben ignorar.

5 Actualizar el archivo en el futuro

Para subir una versión nueva del recurso:

  1. Ir a Releases en el repositorio.
  2. Pulsar Draft a new release.
  3. Crear una nueva etiqueta, por ejemplo: v1.1.
  4. Subir el nuevo archivo con el mismo nombre que el anterior.
  5. Pulsar Publish release.
La URL no cambia Si se usa el enlace con /latest/, la URL seguirá siendo válida y apuntará automáticamente a la última versión publicada.

6 Publicar y compartir

Con la URL estable del paso 4, puedes compartir el recurso públicamente con Visor Web-ZIP pegando esa dirección en el campo Crear enlace.

  1. Abre visor-webzip.github.io.
  2. En la zona ② Crear enlace, pega la URL estable de GitHub (https://github.com/USUARIO/REPO/releases/latest/download/archivo.ext).
  3. Pulsa Crear enlace y comparte el enlace generado con tu alumnado.

✓ Resultado final

Con este procedimiento se obtiene:

  • Un repositorio en GitHub que actúa como contenedor de archivos.
  • Un sistema de alojamiento para archivos grandes (hasta 2 GB por archivo).
  • Una URL pública, directa y estable que siempre apunta a la última versión.
  • Un historial de versiones con las releases anteriores siempre accesibles.

Todo el proceso se realiza desde el navegador, sin necesidad de instalar programas ni usar la terminal.
